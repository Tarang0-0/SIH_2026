# Plan 02-01: Event Ingestion Pipeline & Deterministic Replay Feed

## Objective
Build the production FastAPI event ingestion service (`POST /api/v1/running-updates`), database state transition manager, and deterministic replay simulator script (`scripts/replay_simulator.py`) using the canonical event contract.

---

## Technical Context & Constraints
- **Canonical Schema**: Must strictly consume `CanonicalTrainEvent` from `backend/app/schemas/event.py`.
- **System of Record**: Store append-only event logs in Supabase `running_updates` table and update active state in `journeys`.
- **Invariants**:
  - Out-of-order events ($T < T_{last}$) are persisted in `running_updates` but do not mutate `journeys.current_delay_minutes`.
  - Speed range $0.0 \le \text{speed} \le 220.0 \text{ km/h}$; invalid speed returns HTTP 400.
  - Replay simulator explicitly sets `"source": "SIMULATED"` on all events.

---

## Tasks

### Task 1: Create Ingestion Service (`backend/app/services/ingestion.py`)
- Implement `process_running_update(event: CanonicalTrainEvent, db: Client) -> dict`:
  - Validate station codes (`current_station`, `next_station`) exist in `stations` table.
  - Insert event log record into `running_updates`.
  - Fetch latest `journeys` record for `event.journey_id`.
  - If event timestamp $\ge$ `journeys.updated_at` (or `updated_at` is NULL):
    - UPDATE `journeys` with `current_station_id`, `next_station_id`, `current_delay_minutes`, `current_speed_kmph`, `data_source`, `updated_at`.
    - Return `journey_state_updated = True`.
  - If out-of-order ($T < \text{journeys.updated\_at}$):
    - Return `journey_state_updated = False`.

### Task 2: Create Ingestion Route (`backend/app/api/v1/endpoints/ingestion.py`)
- Define `POST /api/v1/running-updates`:
  - Accept `CanonicalTrainEvent` JSON payload.
  - Return `200 OK` on clean ingestion with structured metadata (`running_update_id`, `journey_state_updated`, `data_source`).
  - Return `400 Bad Request` if `speed_kmph > 220.0` or coordinates out of bounds.
  - Return `404 Not Found` if journey or station code does not exist in DB topology.
- Register route in `backend/app/main.py`.

### Task 3: Create Replay Simulator & Fixtures (`scripts/replay_simulator.py` & `scripts/fixtures/j1001_replay_events.json`)
- Create `scripts/fixtures/j1001_replay_events.json`:
  - Deterministic sequence of 10 events for train 12004 (NDLS $\rightarrow$ LKO) through GZB, ALJN, CNB, LKO.
  - Demonstrates accumulating delay (0m $\rightarrow$ 8m $\rightarrow$ 14m) and recovery.
- Create `scripts/replay_simulator.py`:
  - CLI script with `--journey-id`, `--speed-multiplier`, `--api-url`, `--loop`.
  - Reads fixture, streams events to FastAPI endpoint at calculated intervals.
  - Sets `"source": "SIMULATED"` on all events.

---

## Verification Criteria
- `POST /api/v1/running-updates` returns HTTP 200 for valid events.
- Replay simulator script runs cleanly against FastAPI backend without validation errors.
- Database `running_updates` receives event log and `journeys` reflects latest state.
