# Plan 06-01: Interactive What-If Disruption Simulator UI & Backend API

## Goal
Build an interactive what-if disruption simulator allowing evaluators to inject custom operational disruptions (Signal Failure, Track Maintenance, Weather Fog, Locomotive Fault) and immediately observe downstream cascading delay adjustments, confidence interval shifts, and SHAP explainability recalculations.

## Proposed Architecture & Changes

### 1. Disruption Simulation Backend Endpoint
- **File**: `backend/app/api/v1/endpoints/simulator.py`
- `POST /api/v1/simulate/disruption`
  - Payload: `{ "journey_id": "J1001", "additional_delay_minutes": 25, "section_from": "GZB", "section_to": "ALJN", "disruption_type": "Signal Failure" }`
  - Ingests simulated event, applies operational delay delta to journey state, computes new cascading GBDT ETA forecast with residual intervals and SHAP attribution, and broadcasts live update to connected WebSocket clients.

### 2. Frontend Disruption Simulator Modal
- **File**: `frontend/src/components/DisruptionSimulatorModal.tsx`
- Interactive modal with:
  - Disruption preset selector: Signal Failure (+20m), Winter Fog (+35m), Track Maintenance (+45m), Locomotive Defect (+15m), Custom.
  - Delay duration slider (-15m to +90m).
  - Target section dropdown (`GZB → ALJN`, `ALJN → CNB`, etc.).
  - Instant "Simulate Disruption" button triggering live prediction recalculation and UI hydration.
