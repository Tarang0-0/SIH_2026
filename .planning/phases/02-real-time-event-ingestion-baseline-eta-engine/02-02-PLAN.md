# Plan 02-02: Baseline ETA Calculation Engine & Verification Suite

## Objective
Implement the Schedule-Based Baseline ETA Calculation Engine ($\text{Scheduled Arrival} + \text{Current Observed Delay}$), station delay propagation REST API (`GET /api/v1/trains/{id}/eta`), database persistence into `eta_predictions`, and comprehensive Pytest test suite covering all 13 mandated test cases.

---

## Technical Context & Constraints
- **Baseline Formula**: $\text{Baseline ETA}_s = \text{Scheduled Arrival}_s + \text{Current Delay}$.
- **Zero Future Information**: Does not extrapolate current speed, assume future recovery, or use ML models.
- **Topology Source**: Derived from `route_stations` database topology.
- **No Fabricated Information**: All prediction outputs include `data_source` tag.

---

## Tasks

### Task 1: Create Baseline Calculation Engine (`backend/app/services/baseline.py`)
- Implement `calculate_baseline_eta(journey_id: str, db: Client = None) -> ETAPredictionResponse`:
  - Fetch journey state from `journeys` table (or mock topology fallback if DB offline).
  - Lookup route topology from `route_stations` ordered by `sequence_number ASC`.
  - Identify current station sequence and filter upcoming stations ($sequence > current\_sequence$).
  - For each upcoming station:
    - Combine `journey_date` + `scheduled_arrival` (with overnight rollover logic if arrival < departure).
    - Add `current_delay_minutes` to compute `baseline_eta` ISO timestamp.
    - Set `predicted_eta` equal to `baseline_eta` for Phase 2 baseline benchmarking.
    - Compute baseline residual confidence bounds: `lower_bound_minutes = max(0, delay - 3)`, `upper_bound_minutes = delay + 5`.
  - Persist predictions into `eta_predictions` table.
  - Return `ETAPredictionResponse`.

### Task 2: Create ETA Prediction API (`backend/app/api/v1/endpoints/eta.py`)
- Define `GET /api/v1/trains/{id}/eta` (where `{id}` is `journey_id` or `train_number`):
  - Returns `ETAPredictionResponse` with station-by-station baseline ETAs, confidence range bounds, and data provenance.
- Define `GET /api/v1/predictions/{journeyId}/history`:
  - Returns historic prediction log from `eta_predictions` table.
- Register routes in `backend/app/main.py`.

### Task 3: Comprehensive Pytest Test Suite (`backend/tests/test_ingestion_and_baseline.py`)
- Implement 13 mandated test cases:
  1. Valid event ingestion (`POST /api/v1/running-updates` returns HTTP 200).
  2. Malformed payload (missing required fields returns HTTP 422).
  3. Duplicate event handling (idempotent state update).
  4. Out-of-order event handling (log stored, newer state preserved).
  5. Stale event ingestion ($> 30$ min old flags journey as stale).
  6. Impossible speed validation ($> 220$ km/h rejected with HTTP 400).
  7. Invalid coordinates validation (latitude out of range rejected with HTTP 400).
  8. Negative delay handling (ahead of schedule subtracts delay).
  9. Unrecognized current station code (returns HTTP 404).
  10. Baseline ETA formula calculation ($\text{Scheduled} + \text{Delay}$ match).
  11. Terminal station baseline calculation.
  12. Multiple upcoming stations sequence order matching `route_stations`.
  13. Replay simulator fixture file parsing & integrity verification.

---

- `PYTHONPATH=. ./venv/bin/pytest tests/` passes 100% of test cases cleanly.
- `GET /api/v1/trains/J1001/eta` returns structured baseline station ETAs.
- Ingesting a new event with $+15\text{ min}$ delay instantly recalculates downstream baseline ETAs for all upcoming stations.
